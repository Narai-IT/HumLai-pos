# เปิดหน้าเว็บ POS จากเซิร์ฟเวอร์ร้าน (เลิกพึ่ง Vercel)

เดิมหน้าเว็บอยู่บน Vercel ส่วน API อยู่ที่เครื่องในร้าน ตอนนี้ API Server เปิดหน้าเว็บให้ด้วย
หน้าเว็บกับ API จึงอยู่ที่อยู่เดียวกัน ไม่มีโควตา Vercel ให้กังวล และไม่ติดเงื่อนไขแพ็กเกจฟรีของ Vercel

```
มือถือลูกค้า / เครื่องพนักงาน
        ↓  https://humlai.naraipizzeria.com   ← หน้าเว็บ + API ที่อยู่เดียวกัน
   Cloudflare Tunnel
        ↓
เครื่องในร้าน: API Server พอร์ต 8080  (โฟลเดอร์ dist = หน้าเว็บ)
        ↓
   SQL Server
```

## ขั้นที่ 1 — อัปเดตเครื่อง API

รัน **`update-api.bat`** (Run as administrator) ตามปกติ ตอนนี้มีขั้น **[4/5] สร้างหน้าเว็บ POS** เพิ่มมา (ใช้เวลาไม่ถึง 1 นาที)
ทุกครั้งที่อัปเดตครั้งต่อไป หน้าเว็บจะถูกสร้างใหม่ให้อัตโนมัติ

ทดสอบที่เครื่องนั้น: เปิด <http://localhost:8080/> ต้องเห็นหน้าเลือกสาขาของ POS

> ถ้าขั้น [4/5] ขึ้น "สร้างหน้าเว็บไม่สำเร็จ" ส่งข้อความในหน้าต่างนั้นมาให้ดู — หน้าเว็บบน Vercel ยังใช้ได้ตามปกติระหว่างนี้

## ขั้นที่ 2 — เพิ่มที่อยู่ humlai.naraipizzeria.com ใน Cloudflare Tunnel

ใช้ tunnel ตัวเดิม (**narai-48** — ตัวเดียวกับที่มี `pos-api.khanoykorshabu.com`) เพิ่มชื่อใหม่ที่ชี้ไปพอร์ตเดียวกับ API

1. ดูก่อนว่า `pos-api` ชี้ไปที่ไหน: หน้า tunnel narai-48 → แท็บ **Routes** → คลิกแถว `pos-api.khanoykorshabu.com`
   จดค่า **Service / URL** ไว้ (ปกติคือ `http://localhost:8080`)
2. กลับมาหน้า Overview → ปุ่ม **+ Add route** → เลือก **Published application**
3. ใส่ค่า:

   | ช่อง | ใส่อะไร |
   |---|---|
   | Subdomain | `humlai` |
   | Domain | `naraipizzeria.com` |
   | Path | เว้นว่าง |
   | Service Type | `HTTP` |
   | URL | ค่าเดียวกับที่จดจาก `pos-api` ในข้อ 1 (ปกติ `localhost:8080`) |

4. กด **Save** — Cloudflare สร้าง DNS `humlai.naraipizzeria.com` ให้เอง ใช้ได้ภายในไม่กี่นาที
   (ถ้าขึ้นว่ามี DNS record ชื่อนี้อยู่แล้ว ให้ลบแถว `humlai` เดิมในหน้า DNS ของ naraipizzeria.com ก่อน)

ทดสอบ: เปิด `https://humlai.naraipizzeria.com` จากมือถือที่**ไม่ได้**ต่อ Wi-Fi ร้าน ต้องเห็นหน้าเลือกสาขา
แล้วลองหน้าลูกค้า `https://humlai.naraipizzeria.com/kiosk?table=1` สั่งอาหารได้ครบจนแจ้งโอน

## ขั้นที่ 3 — Vercel ส่งต่อไปที่อยู่ใหม่

หลังขั้นที่ 2 ผ่านแล้ว Vercel ถูกเปลี่ยนให้เหลือหน้าเดียวที่**ส่งต่อไปที่อยู่ใหม่อัตโนมัติ** (scripts/build-vercel-redirect.mjs):

- สติกเกอร์ QR โต๊ะที่ชี้ `hum-lai-pos.vercel.app` ใช้ต่อได้เลย สแกนแล้วไปหน้าสั่งอาหารโต๊ะเดิม สาขาเดิม ที่อยู่ใหม่
  (ใช้โควตา Vercel 1 คำขอต่อการสแกน)
- เครื่องพนักงานที่เปิดที่อยู่เดิม จะถูกส่งต่อไปที่อยู่ใหม่ พร้อม**ค่าตั้งของเครื่อง** (สาขาที่เลือก เครื่องพิมพ์) ตามไปด้วย
  ล็อกอินพนักงานใหม่หนึ่งครั้ง แล้วบุ๊กมาร์ก/ปักหมุดที่อยู่ใหม่ไว้
- ถ้าเครื่องนั้นมี**บิลค้างส่ง** จะขึ้นหน้าต่างถามว่าจะนำเข้าไหม (แสดงโต๊ะ/ยอด) กด "ตกลง" แล้วระบบส่งขึ้นและพิมพ์ใบกำกับภาษีตามให้
  บิลที่เคยส่งสำเร็จแล้วจะไม่ถูกบันทึกซ้ำ
- พิมพ์ QR โต๊ะชุดใหม่: เปิดหลังบ้านจาก `https://humlai.naraipizzeria.com` → จัดการโต๊ะ → **พิมพ์ QR ทุกโต๊ะ**
  (A4 แผ่นละ 6 ดวง ตัดตามเส้นประ · ใต้ QR มีชื่อที่อยู่เล็ก ๆ ให้เช็กว่าเป็น humlai.naraipizzeria.com) ทำทีละสาขา
- เปลี่ยนที่อยู่ปลายทางภายหลัง: ตั้ง `REDIRECT_TO=https://ที่อยู่ใหม่` ใน Vercel → Settings → Environment Variables แล้ว Redeploy
- เก็บ Vercel ไว้ส่งต่อสัก 1–2 เดือน (เผื่อ QR ที่ลืมเปลี่ยน ลิงก์ในโพสต์ LINE บุ๊กมาร์กลูกค้า) แล้วค่อยปิดโปรเจกต์ได้

## ข้อควรรู้

- **เครื่องในร้านต้องเปิดอยู่** หน้าเว็บถึงจะเปิดได้ (เหมือน API ที่ต้องเปิดอยู่แล้วตอนนี้) — ไฟดับ/เน็ตร้านหลุด
  เครื่องที่เปิดหน้าเว็บค้างไว้ยังขายต่อได้ บิลจะค้างไว้ส่งเองเมื่อเน็ตกลับมาเหมือนเดิม แต่ถ้ารีเฟรชหน้าตอนนั้นจะเปิดไม่ขึ้น
- **รูปเมนูที่เป็นลิงก์ ImgBB / Google Drive** เซิร์ฟเวอร์ร้านย่อรูปเองแล้วเก็บไว้ในโฟลเดอร์ `cache\img` (แทนตัวย่อรูปของ Vercel)
  ครั้งแรกที่เปิดแต่ละรูปจะช้ากว่าปกตินิดหน่อย ครั้งต่อไปเร็วเหมือนเดิม — ลบโฟลเดอร์นี้ทิ้งได้ทุกเมื่อ ระบบสร้างใหม่เอง
- **Cloudflare แคชไฟล์โค้ดหน้าเว็บ (.js .css) และรูปในโฟลเดอร์ images** ให้เองตามค่าเริ่มต้น ลูกค้าส่วนใหญ่จึงโหลดไฟล์เหล่านี้จาก Cloudflare ไม่ได้ดึงจากเน็ตร้านทุกครั้ง
